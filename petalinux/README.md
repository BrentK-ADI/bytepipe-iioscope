# Petalinux with Bytepipe BSP
The following information describes how to utilize the BytePipe BSP to create
Petalinux projects for the BytePipe SOM.

A Petalinux BSP is a self contained archive which includes all the necessary
configuration and additional files (such as device trees and patches) needed
to generate a Petalinux project for a specific piece of hardware.  This eliminates
the need to manually copy in device tree files or utilize the Petalinux menu
configuration system for setting the project up.

In addition to the standard Petalinux configuration data, this BSP also includes
meta-adi sourced from https://github.com/analogdevicesinc/meta-adi, version
2023_R2, which includes ADI's Linux kernel, libiio, as well as other useful
features for utilizing the ADRV9002 and supporting tools.

## Creating, Configuring and Building the Project
To create the Petalinux project based on the BSP, run the following command:
`petalinux-create -t project -n <project name> -s bytepipe.bsp`

For example, if we wanted our project to be called `bytepipe-demo`, the command
would be:

`petalinux-create -t project -n bytepipe-demo -s bytepipe.bsp`.

Once run, a new folder based on the project name will be present. This is the
Petalinux project folder.   Next, to load the correct hardware (XSA) file, the
following command is run `petalinux-config -p <project name> --silentconfig --get-hw-description=<XSA file>`

Once again using the `bytepipe-demo` project, and assuming a XSA generated by
the BytePipe HDL scripts, the command would be:

`petalinux-config -p bytepipe-demo --silentconfig --get-hw-description=./system_xczu3cg-sbva484-1-e_lvds.xsa`

Once complete, the project is configured and ready to be built using `petalinux-build`

## Deploying
To deploy the project, use the standard Petalinux methods.  One method:

`petalinux-package --boot --fsbl --fpga --u-boot --force` to generate the SD
Card artifacts.

Then copy `images/linux/BOOT.BIN`, `images/linux/boot.scr`, and `images/linux/image.ub`
to the BOOT partition of the SD Card.

## Modifying the BSP
Since the BSP is based on the project-spec files of a project, any project
that leverages the BSP can be the source of updates or changes.  Following the
steps above, create a new project using the BSP file.

Make the necessary changes to the project, such as adding new patch files,
kernel configurations and other features.

Once the project has been tested, the BSP can be built.  Since the BSP is just
an archive of project-spec data, it is recommended to clean the project before
creating the BSP to eliminate any unnecessary artifacts from getting included.
To do this, run `petalinux-build -x mrproper`

Once the project is cleaned up, run the following command to package the BSP:
`petalinux-package --bsp -p <project name> --clean -o <output file> --force --exclude-workspace`

Once again, with `bytepipe-demo` as the project and `bytepipe.bsp` as the output,
the command would be: `petalinux-package --bsp -p bytepipe-demo --clean -o bytepipe.bsp --force --exclude-workspace`.

The BSP archive is ready for use and configuration management.
